# Identidade Visual — Portfólio Eduardo Ruiz

## 1. Visão geral

Este projeto é o portfólio pessoal de Eduardo Ruiz, desenvolvedor web Full Stack.

Site:

https://oduardoruiz.github.io/eduardoruiz/

O objetivo visual do projeto é apresentar um portfólio profissional de tecnologia utilizando uma estética inspirada no movimento Bauhaus, porém reinterpretada de forma contemporânea.

A identidade deve transmitir:

* tecnologia;
* criatividade;
* organização;
* personalidade;
* profissionalismo;
* simplicidade;
* precisão;
* desenvolvimento de software.

A estética não deve parecer um template genérico de portfólio de desenvolvedor.

O site deve possuir personalidade própria e utilizar princípios de design gráfico, especialmente composição geométrica, contraste, assimetria controlada e uso consciente de cores.

---

# 2. Direção visual

A referência principal é:

**Bauhaus contemporânea + design editorial + interface moderna.**

Não reproduzir literalmente cartazes históricos da Bauhaus.

Utilizar os conceitos:

* formas geométricas simples;
* círculos;
* quadrados;
* retângulos;
* linhas;
* blocos de cor;
* assimetria;
* contraste;
* espaço negativo;
* tipografia forte;
* composição modular.

Os elementos geométricos devem funcionar como parte da identidade visual e não apenas como decoração aleatória.

# 4. Regra de utilização das cores

Evitar utilizar todas as cores fortes simultaneamente.

A composição deve priorizar:

**Grafite + Marfim + uma cor de destaque**

ou

**Azul petróleo + Marfim + Terracota**

ou

**Areia + Grafite + Mostarda**

As cores fortes devem funcionar como elementos de destaque.

Evitar uma interface em que todos os elementos possuem cores diferentes.

A sensação desejada é:

**80% cores neutras / 20% cores de destaque.**

---

# 5. Tipografia

A tipografia deve ser moderna, limpa e altamente legível.

Priorizar uma fonte sans-serif contemporânea.

A hierarquia deve ser forte:

### Títulos

Grandes, pesados e visualmente marcantes.

Preferir:

* peso 700 ou 800;
* letras grandes;
* line-height compacto;
* composição editorial.

### Subtítulos

Peso médio ou semibold.

### Texto

Regular, confortável para leitura.

### Pequenos elementos

Pode utilizar:

* uppercase;
* letter-spacing;
* labels;
* pequenas categorias.

Evitar fontes excessivamente decorativas.

A tipografia deve complementar a geometria do layout.

---

# 6. Estrutura visual

A landing page deve possuir bastante espaço negativo.

Evitar excesso de informação visual.

O layout deve utilizar:

* grids;
* colunas;
* espaçamento consistente;
* blocos;
* alinhamentos fortes;
* elementos assimétricos.

O conteúdo deve ser fácil de escanear.

---

# 7. Elementos geométricos

Elementos geométricos são parte importante da identidade.

Utilizar:

* círculos;
* quadrados;
* retângulos;
* linhas;
* barras;
* pequenos blocos coloridos.

Esses elementos podem aparecer:

* atrás de títulos;
* nos cards;
* nos backgrounds;
* em áreas de destaque;
* na seção de contato;
* em detalhes de projetos.

Os elementos não devem prejudicar a leitura.

Evitar excesso de formas em uma única área.

---

# 8. Cards

Os cards não devem parecer componentes genéricos de Bootstrap.

Sempre que possível, utilizar a estrutura existente e adicionar personalidade através de:

* bordas;
* blocos de cor;
* barras laterais;
* elementos geométricos;
* tipografia;
* contraste;
* pequenos indicadores.

A geometria deve fazer parte do card.

---

`#202020`

`#F5F0E6`

---

# 10. Interações

As interações devem ser discretas.

Utilizar:

* hover;
* pequenas transições;
* deslocamento mínimo;
* mudança de borda;
* alteração de cor;
* pequenas animações geométricas.

Evitar:

* animações exageradas;
* efeitos neon;
* parallax excessivo;
* elementos piscando;
* movimentos rápidos;
* efeitos que prejudiquem a leitura.

O movimento deve parecer sofisticado e intencional.

---

# 11. Seção de Contato

A seção de contato deve funcionar como o encerramento visual da landing page.

Deve ser uma das áreas de maior impacto.

A composição pode utilizar:

* Azul petróleo `#155E63`;
* Terracota `#C94C35`;
* Mostarda `#D6A72C`;
* Marfim `#F5F0E6`.

O título:

**Let's build something.**

deve possuir grande destaque.

A área de contato deve parecer um grande bloco gráfico Bauhaus e não apenas uma lista de links.

---

# 12. Links de contato

Links atuais:

* GitHub
* LinkedIn
* E-mail
* WhatsApp

Os links devem possuir forte presença visual.

Podem utilizar:

* ícones;
* blocos;
* linhas;
* bordas;
* mudanças de cor;
* elementos geométricos.

GitHub, LinkedIn e WhatsApp devem preferencialmente utilizar ícones de marca apropriados.

Ícones genéricos podem ser utilizados para funcionalidades como e-mail.

---

# 13. Ícones

A interface pode utilizar Lucide para ícones genéricos.

Exemplos:

* mail;
* arrow;
* external-link;
* menu;
* chevron;
* etc.

Para marcas:

* GitHub;
* LinkedIn;
* WhatsApp;

preferir uma biblioteca especializada em brand icons ou SVGs próprios.

Evitar substituir logos conhecidos por ícones genéricos quando a identidade da plataforma for importante.

---

# 14. Responsividade

A identidade visual deve funcionar em:

* desktop;
* notebook;
* tablet;
* celular.

Os elementos geométricos devem se adaptar ao viewport.

Nunca permitir:

* overflow horizontal;
* conteúdo cortado;
* elementos sobrepostos de forma acidental;
* texto ilegível;
* botões fora da tela.

No mobile, a composição deve ser reorganizada e não simplesmente reduzida.

---

# 15. Bootstrap

O projeto utiliza Bootstrap.

Bootstrap pode continuar sendo utilizado para:

* grid;
* responsividade;
* espaçamentos;
* componentes estruturais.

Porém, evitar deixar a interface com aparência padrão do Bootstrap.

A camada visual personalizada deve prevalecer.

---

# 16. CSS

Priorizar CSS organizado e reutilizável.

Evitar criar dezenas de estilos específicos para um único elemento.

Sempre verificar se já existe alguma classe reutilizável antes de criar outra.

Preferir variáveis CSS para a identidade visual:

```css
:root {
    --bauhaus-terracotta: #C94C35;
    --bauhaus-mustard: #D6A72C;
    --bauhaus-petrol: #155E63;
    --bauhaus-graphite: #202020;
    --bauhaus-ivory: #F5F0E6;
    --bauhaus-sand: #D9D0C1;
}
```

---

# 17. Filosofia de implementação

O site deve ser evoluído, não reconstruído.

Antes de alterar qualquer seção:

1. analisar o HTML atual;
2. analisar o CSS atual;
3. entender as classes existentes;
4. identificar componentes reutilizáveis;
5. preservar o conteúdo existente;
6. preservar funcionalidades;
7. fazer alterações mínimas e controladas.

Não realizar redesign completo sem solicitação explícita.

---

# 18. O que evitar

Não utilizar:

* neon;
* glassmorphism;
* gradientes excessivos;
* sombras exageradas;
* excesso de border-radius;
* cards genéricos;
* excesso de animações;
* excesso de cores;
* estética cyberpunk;
* estética futurista genérica;
* visual de dashboard;
* elementos decorativos sem função.

A identidade deve continuar sendo:

**Bauhaus contemporânea + tecnologia + design editorial.**

---

# 19. Personalidade visual desejada

Ao olhar para o site, a primeira impressão deve ser:

"Este é um desenvolvedor, mas ele possui uma identidade visual própria."

O design deve equilibrar:

**Tecnologia**
+
**Design**
+
**Personalidade**
+
**Profissionalismo**

O site deve parecer autoral, organizado e moderno, sem perder a simplicidade.

---

# 20. Regra principal para futuras alterações

Antes de implementar qualquer alteração visual, verificar:

> "Isso parece fazer parte do mesmo sistema visual do portfólio Eduardo Ruiz?"

Se a resposta for não, adaptar a solução à identidade existente.

Não introduzir uma nova linguagem visual sem necessidade.

A prioridade deve ser sempre:

**consistência > efeitos**

**hierarquia > decoração**

**legibilidade > complexidade**

**identidade > tendência**
